# Guardian Brainstorm

1. Inspect current project context and confirmed requirements.
2. Separate independent subsystems when the request is too broad.
3. Ask only questions whose answers materially change the design.
4. Present two or three approaches with trade-offs and a recommendation.
5. Record architecture, data flow, failure handling, security, and tests.
6. Obtain explicit design approval before high-risk implementation.

For small reversible tasks, write a short design and continue without unnecessary ceremony.
